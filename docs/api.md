# API импорта фотографий

Контракт одинаковый для обоих сайтов, но адреса, ключи, журналы и лимиты у каждого свои. Ключ сайта A не принимается сайтом D (раздел 11.1 ТЗ).

## Ключ доступа

Ключ выпускается в админке: «API импорта — ключи → Добавить».
1. Укажите понятное имя подключения.
2. Отметьте дополнительные права, если они согласованы. По умолчанию ключ умеет только загружать фото в рубрики.
3. Сохраните. Ключ покажется **один раз** — скопируйте его сразу.

На сервере хранится только проверочный хеш ключа. Отозвать ключ можно действием «Отозвать выбранные ключи». Уже загруженные файлы при этом останутся.

| Право | По умолчанию | Что даёт |
|---|---|---|
| Загрузка фотографий в рубрики | всегда | принимает файл в указанную рубрику; файл остаётся непубличной записью импорта |
| Замена обложки рубрики | выкл. | `purpose=cover` заменяет обложку рубрики |
| Создание карточек-черновиков | выкл. | для каждого фото создаётся карточка «Под заказ» с общим описанием и общим списком размеров (черновик) |
| Публикация созданных карточек | выкл. | созданные карточки сразу публикуются |

Импорт никогда не назначает цену, фактический размер, технику и статусы «В наличии» или «Продана».

## Запросы

Все запросы идут по HTTPS с заголовком `Authorization: Bearer <ключ>`.

### `GET /api/v1/import/categories`

Возвращает рубрики с постоянными ID. ID не меняется при переименовании рубрики.

```json
{"ok": true, "categories": [{"id": 8, "parent_id": null, "name": "Море", "name_en": "Seascapes",
  "path": "Море", "visible": true}]}
```

### `POST /api/v1/import/images` (multipart/form-data)

| Поле | Обязательно | Описание |
|---|---|---|
| `file` | да | JPG, PNG или WEBP. Реальный формат проверяется, изображение декодируется и пересохраняется |
| `external_id` | да | уникальный ID файла у вас (до 200 символов). По нему узнаются повторы |
| `category_id` | да | ID рубрики. Несуществующая рубрика отклоняется: похожая не подбирается, новая не создаётся |
| `purpose` | нет | `photo` (по умолчанию) или `cover` (нужно право замены обложки) |

Ответ `201`:

```json
{"ok": true, "duplicate": false, "external_id": "IMG-1", "record_id": 15, "category_id": 8,
 "purpose": "photo", "state": "accepted", "state_display": "Принят, ждет назначения",
 "painting_id": null, "width": 3000, "height": 2400}
```

Повтор с тем же `external_id` и тем же файлом возвращает `200` и `"duplicate": true`. Дубль не создаётся.

### `GET /api/v1/import/results/<external_id>`

Показывает результат по ранее отправленному файлу. Нужен, чтобы после обрыва связи проверить, дошёл ли файл.

## Коды ошибок

| Код | `error` | Причина |
|---|---|---|
| 400 | `external_id_required`, `category_required`, `file_required`, `bad_purpose` | не хватает поля или оно неверное |
| 401 | `unauthorized` | неверный или отозванный ключ, ключ другого сайта |
| 403 | `forbidden`, `https_required` | нет права на действие; запрос не по HTTPS |
| 404 | `category_not_found`, `not_found` | нет такой рубрики или такого `external_id` |
| 409 | `conflict` | `external_id` уже занят другим файлом (перезапись без права не выполняется) |
| 413 | `file_too_large`, `too_many_pixels` | превышен лимит размера файла или числа пикселей |
| 415 | `unsupported_format` | файл не распознан как JPG, PNG или WEBP |
| 429 | `rate_limited` | слишком много запросов в минуту |

Лимиты задаются в `.env`: `IMPORT_MAX_FILE_MB` (по умолчанию 40), `IMPORT_MAX_PIXELS` (80 млн), `IMPORT_RATE_PER_MINUTE` (60). Их стоит подобрать по реальным фотографиям.

## Пример на curl

```bash
curl -H "Authorization: Bearer $TOKEN" https://mirame.ru/api/v1/import/categories
curl -H "Authorization: Bearer $TOKEN" -F external_id=IMG-0001 -F category_id=8 \
     -F file=@sea.jpg https://mirame.ru/api/v1/import/images
```

## Загрузчик для компьютера владельца

Скрипт `tools/uploader.py` работает на Python 3.9 и новее, дополнительные пакеты не нужны.

1. Скопируйте `tools/uploader.example.ini` в `uploader.ini` и заполните профили `mirame` и `holstory`: адрес сайта, файл с ключом, соответствие «папка → ID рубрики».
2. Сохраните ключ в отдельный файл, например `~/.config/art-uploader/mirame.token`. Не храните его в репозитории, в ini-файле и в переписке.
3. Посмотрите ID рубрик: `python uploader.py --config uploader.ini --profile mirame --categories`.
4. Проверьте план без загрузки: `python uploader.py --config uploader.ini --profile mirame --dry-run`.
5. Загрузите: `python uploader.py --config uploader.ini --profile mirame`. Перед загрузкой скрипт покажет домен и назначения и попросит подтверждение.

Если загрузка прервалась, просто запустите её снова: уже принятые файлы сервер узнает, дублей не будет.

Принятые фото видны в админке в разделе «API импорта — принятые файлы». Там их можно назначить существующей картине (поле «Назначить картине») или создать из них карточки-черновики (групповое действие).

**Замена ключа:** выпустите новый ключ, запишите его в файл ключа, затем отзовите старый.
